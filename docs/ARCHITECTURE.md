# Архитектура MeowShot

## Процесс приложения

MeowShot запускает один STA-процесс без постоянного главного окна. `HotkeyService` создаёт скрытое message-only окно и регистрирует `Ctrl + Shift + S` через `RegisterHotKey`. Повторный запуск отсекается именованным mutex.

## Захват

`ScreenCaptureService` получает рабочий стол в физических пикселях через GDI `BitBlt` с флагом `CAPTUREBLT`. Снимок создаётся **до** появления оверлея, поэтому затемнение и панель инструментов не попадают в изображение.

Для каждого монитора создаётся отдельное окно `CaptureOverlayWindow`. Его Win32-позиция задаётся в физических координатах монитора, а координаты WPF преобразуются обратно в пиксели перед обрезкой. Это уменьшает проблемы смешанного DPI.

Режим окна использует список видимых верхнеуровневых окон, полученный до показа оверлея. Границы берутся через DWM `DWMWA_EXTENDED_FRAME_BOUNDS`.

## Результат

Выбранная область обрезается из неизменённого общего снимка и замораживается как `BitmapSource`. В буфер помещаются стандартное bitmap-представление и PNG-поток. При автосохранении используется `PngBitmapEncoder`.

## Редактор

Исходный bitmap и векторные WPF-аннотации находятся на Canvas в координатах исходных пикселей. Viewbox изменяет только отображаемый масштаб. При копировании и сохранении Canvas рендерится в исходный размер через `RenderTargetBitmap`.

Undo/redo хранит до 12 PNG-состояний. Это ограничивает память на больших 4K-снимках ценой небольшой задержки при создании состояния.

## Данные пользователя

- настройки: `%LocalAppData%\MeowShot\settings.json`;
- история: `%LocalAppData%\MeowShot\History`;
- автозапуск: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`;
- автосохранение: только в папку, выбранную пользователем.

Сетевых запросов приложение не выполняет.
